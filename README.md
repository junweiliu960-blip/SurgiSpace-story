# SurgiSpace 外科密室 · 双病例故事网页重制版

按2026年11月13日制作策划组织主线，复用既有题库、实时剧情系统与Lux3D资产，在独立目录重制菜单与账号存档。

## 开始游戏

线上入口由 Sites 发布结果提供。网页使用 ChatGPT 账号登录，点击“开始问诊”开始新故事；返回玩家选择“继续上次任务”。右下角云端按钮提供保存状态、备份、冲突恢复和保存退出。新站保持仅所有者可访问；尚未开放给其他玩家。

## 本地运行

需要Node 22.12或更高版本。运行 npm ci，然后 npm run dev，打开 http://127.0.0.1:5186/ 。本机预览使用独立演示账号，进度保存在 .local/players，不连接线上账号。npm test 验证故事状态、动画时间轴及云存档；npm run build 生成 dist/client 与 dist/server/index.js。

## 已接入的故事

投资亏损与来电、三项资料核查、接机、车内黑场、胁迫、林先生20个医疗节点、术后复查与拒绝放行、纸条、周先生5个问诊及6个腹腔镜决策、恢复交接、身份揭示及护送获救。首读剧情需要完成，已读可回顾与跳过；纸条需要主动查看。

## 玩家进度

服务端通过 Sites 注入的身份识别玩家，不接受客户端指定玩家ID。R2按账号保存完整故事、两病例、选项与重试记录、阅读线索和设置。条件写入及修订号防止多设备互相覆盖。离线写入保留本机待同步副本，重新连接后可重试；冲突时主动读取云端并保留本机备份，不自动覆盖。退出前等待保存成功。

## 与策划的差异和验收边界

这是可运行的游戏制作版本，不能声明已经完成项目书全部艺术和医学验收。角色与道具采用已有简化实时三维动画；细节表演、接触精度、声音、手机实机性能及目标玩家试玩仍需逐项验收。没有自由切割或组织力学。阑尾器官为原创教学示意。原项目已修正AD05中“有极大的穿孔可能”的绝对风险措辞，保留该修正，不将其恢复为未经医学证实的风险结论。虚构新闻沿用订单核查危机，不采用桃色新闻。

项目书中的“无需登录”和“不增加新登录后端”由本次用户明确提出的登录恢复需求覆盖：采用Sites现成登录和账号存档。现有version3练习存档可通过原入口导入，但不伪造已完成的故事章节。

public/models中的Lux3D肾脏、人物、铺巾及器械沿用用户既有项目资产，未重新调用生成接口。来源署名、模型处理记录见docs目录及LICENSE。保留BodyParts3D和HRA的CC BY署名。病例、生命体征与操作为教学情境，未经临床认证，不用于真实诊疗。
